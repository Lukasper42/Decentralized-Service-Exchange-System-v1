# Smoke test of skillx-web against a real relay (local, Windows/PowerShell)

Prerequisite: Node 22, `npm install` in skill-exchange-ledger and skillx-web.
Relay in memory mode (RELAY_MODE=memory): everything is gone after a restart.

## A. Prepare the relay (folder skill-exchange-ledger)
1. `npm run build`
2. Relay key: `node dist/apps/relay/admin-cli.js keygen --out relay.key` (note the output `public_key=...`; do not check in relay.key)
3. Start the web UI (step B), create a key in the Identity tab (the UI stores exactly one) and note the pubkey.
4. In the folder skill-exchange-ledger: `node ../tools/manual/make-genesis.mjs "<pubkey from the UI>" "<public_key from step 2>"` (writes genesis-config.json, genesis.json and b-key.json for account B, prints GENESIS_SHA256; an old genesis.json is replaced). Only one key comes from the UI (the UI stores exactly one); account B and the multisig keys are generated by the script.
5. Note GENESIS_SHA256 (or read it later via `(Get-FileHash genesis.json -Algorithm SHA256).Hash.ToLower()`).
6. Start the relay:
   ```
   $env:RELAY_MODE="memory"; $env:GENESIS_FILE="./genesis.json"; $env:GENESIS_SHA256="<hash>"
   $env:RELAY_KEY_FILE="./relay.key"; $env:ALLOWED_ORIGIN="http://127.0.0.1:8080"; $env:PORT="3000"
   npm start
   ```
7. Expectation: the relay runs on 127.0.0.1:3000, `curl http://127.0.0.1:3000/v1/health` returns 200.

## B. Web UI (folder skillx-web)
`npm run build; npm start` -> http://127.0.0.1:8080 (not file://)

## C. Checkpoints (note the result for each: ok / error + text)
1. Status: enter the relay URL http://127.0.0.1:3000 and the pinned relay pubkey (`public_key=` from keygen, 44 bytes SPKI Base64), "Save and connect". Health ok, tip and locally verified length equal.
2. Sync: chain verified without errors, pin set. Restart the relay (storage empty) -> the UI reports rollback/fork; the "Reset remembered chain state" button clears the pin.
3. Identity: create a key, password >= 16 characters; lock, unlock, a wrong password is rejected; auto-lock after 10 min (optional).
4. Account: shows 0 everywhere before the first entry (genesis grants are not ledger entries); totals are derived from the chain only, not authoritative.
5. Explorer: entries are pageable, hashes visible.
6. Deal: export the vault in the UI (Identity, Export), then in the folder skill-exchange-ledger: `node ../tools/manual/deal-test.mjs "<pubkey>" "$HOME\Downloads\skillx-vault.json" '<password>'` (creates accounts and a deal, password in single quotes); the deal is visible in the Deals view.
7. consentDeal: unlock the key, in Deals click "Consent" on the deal as seller (state changes to consented) -> the entry appears, the chain stays verified.
8. castVote: only useful with an assigned jury; otherwise skip and note it.
9. Error cases: wrong relay URL (http://example.com is rejected), relay off (understandable message), wrong ALLOWED_ORIGIN (CORS error visible).
10. Messages (optional, second terminal): skillx-mailbox with `$env:ALLOWED_ORIGIN="http://127.0.0.1:8080"; npm start`; set the mailbox URL, publish the key bundle, send to a second identity, fetch.

## D. Already verified in the sandbox (2026-10-29, Chromium, relay in memory mode)
C1-C7 and C9 ok (status/sync, explorer, unlock including wrong password, account, deals, consentDeal, rollback detection after relay restart, pin reset, relay off, http://example.com rejected). Found and fixed along the way: the relay did not answer the CORS preflight (OPTIONS), so every POST from the browser failed; views stayed empty until the next poll (15 s). C10 (messages, two browser profiles, mailbox on 127.0.0.1:8787) ok: key bundle, send, decrypt, delete; an unknown recipient gives "Recipient has not published a key bundle yet ...". castVote ok with a test genesis (jury thresholds set to 0, for the test only): dispute, 3 jurors (one of them the UI), vote in the UI, resolution 2:1. Not verified with the real beta policy (20 deals, 5 counterparties, 60 days). Not verified: Windows/real browser.
