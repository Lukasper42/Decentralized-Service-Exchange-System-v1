# Test-vector plan — descriptions only

Concrete hashes, keys, signatures and Base64 values are intentionally omitted. Each vector must be generated by implementation code and reused by TypeScript, Go and ABCI implementations.

| Rule | Positive case | Negative case |
|---|---|---|
| E1 | First event per signer null prevHash; next links to that signer's prior event despite interleaving. | Stale signer tip rejected as CHAIN_LINK; two concurrent appends produce one accepted append and one FORK. |
| E2 | Receipt acceptedAt monotone and event timestamp within 5 minutes; replay uses only receipts. | Skew beyond 5 minutes, decreasing acceptedAt, or deadline evaluated using event.timestamp rejected. |
| E3 | Valid receipt sequence 1 then contiguous sequence 2 with correct prior receipt hash, event hash and key id. | Gap, wrong event hash/link, unknown key, bad signature or malformed key range rejected with receipt-specific error. |
| E4 | Amount at min/max; seller release E-F followed by same-signer exact F burn; full buyer refund. | Below min, above max, overflow, wrong fee, duplicate leg, charged refund or signer mismatch rejected. |
| E5 | Seller auto-accept strictly after 7 days with no buyer response. | Auto-accept at boundary or after an existing reject/accept rejected. |
| E6 | Buyer or seller opens dispute within 7 days after rejection. | Dispute without rejection or after window rejected; absent dispute permits refund after window. |
| E7 | Construct eligible sorted pool and verify exact round-0 and round-1 draws from delayed receipt seed; all jurors vote. | Wrong seed sequence/order, ineligible/excluded juror, incomplete quorum, early vote replacement rejected; undersized pool exercises each documented option boundary. |
| E8 | Eligible loser opens once within 3 days, exact appeal fee locked, changed outcome returns fee, unchanged burns fee. | Winner appeals, wrong fee, second appeal, early release, duplicate fee settlement rejected. |
| E9 | One party emits one reputation event after decision; derived dispute deltas project. | Counterparty outside deal, second event for same account/deal, before settlement, or old both_sigs shape rejected. |
| E10 | Two distinct active-policy members approve exact action hash and event signer is one; unique nonce accepted. | One approval, duplicate signer, stale member, altered action preimage, or reused `(action,nonce)` rejected. |
| E11 | Commitment verifies from kind, 32-byte salt and content; EvidenceRevealed publishes valid salt; precheck-report uses empty sentinel. | Wrong domain prefix/salt length or nonempty precheck-report salt rejected; unavailable delivery recorded for jury. |
| E12 | Latest-content precheck from listed checker has effect; unlisted checker event remains valid but ineffective. | Precheck references earlier/nonexistent content hash or invalid attestation rejected. |
| E13 | Valid unused invitation before expiry; genesis null invitation under policy; recovery attestation rotates identity and transfers projection. | Expired/reused invitation, second AccountCreated, bad recovery commitment/signature, old key signing after rotation rejected. |
| E14 | Bootstrap key verifies sequence 1; rotated key signs only its range; clients detect two signed checkpoints at same sequence with different roots. | Unapproved rotation, overlapping range, bad checkpoint or unknown relay key rejected. |
| E15 | Event at activation sequence resolves new policy; earlier event resolves prior policy; first policy active at 1. | Nonincreasing version, duplicate activation, bad params hash or approvals rejected. |
| E16 | Canonical RFC 8032 valid signature verifies identically across implementations. | S≥L, noncanonical R/A, small-order key, bad length or non-roundtripping Base64 rejected. |
| E17 | Every state-table path runs with exact debit/credit and supply equation; expiry only with no escrow. | Funding without consent/funds, funding or delivery at deadline, duplicate transition, release during appeal, or balance mismatch rejected. |
| E18 | Each listed stable code maps to its defined failure and includes offending JSON path. | Malformed input returns a stable code/path, not an uncaught exception or implementation-specific code. |
| E19 | L1 accepts valid stateless envelope; L2 verifies account chain and receipts; L3 replays policy/state/accounting. | L1 does not infer ledger state; L2/L3 reject missing required context rather than substitute system clock or mutable defaults. |
